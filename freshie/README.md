# Freshie — Ecosystem Inventory & Compliance System

Configuration Management Database (CMDB) for the claude-code-plugins ecosystem.

## What This Is

A versioned inventory system that tracks every plugin, skill, agent, command, and file in the repository. Each scan creates a "discovery run" — old data stays, new data appends. Compare runs to see what changed.

**Hybrid storage model (since 2026-07):**

- `freshie/inventory.sqlite` — the **local runtime format**. Every tool
  (validator `--populate-db`, `rebuild-inventory.py`, `enrich-jrig-data.mjs`,
  ad-hoc `sqlite3` queries) reads and writes this file. It is **untracked** —
  the binary blob no longer lives in git.
- **Dolt is the versioned system of record.** `freshie/scripts/dolt-sync.py`
  exports the SQLite DB into a local Dolt repo (`freshie/dolt/freshie/`,
  gitignored) and pushes it to public DoltHub:
  <https://www.dolthub.com/repositories/jeremylongshore/freshie-inventory>.
  Real diffs, queryable history, tagged runs — without a single consumer
  rewrite.
- `freshie/grades.csv` + `freshie/grade-histogram.json` — the **tracked
  compact export**, regenerated by every sync. Their git diff is the
  human-readable "skill X went B→A" story.

> **Local is the sole writer.** Never merge DoltHub PRs, never web-edit the
> public database, never hand-edit `freshie/dolt/`. The exporter is strictly
> one-way (SQLite → Dolt); anything written on the DoltHub side will be
> clobbered and lost on the next sync.

> **Push ≠ backup.** The DoltHub push is what makes history durable and
> publicly visible; borg on the VPS is backup. Until a sync pushes, Dolt
> history is single-copy on this box — which is why `dolt-sync.py` exits
> non-zero and loud when a push fails.

## Quick Start — the full inventory cycle

```bash
# 1. Run a new discovery scan (creates run_id=N+1)
python3 freshie/scripts/rebuild-inventory.py

# 2. Run compliance validation (fills skill/agent/plugin_compliance tables)
python3 scripts/validate-skills-schema.py --marketplace --populate-db freshie/inventory.sqlite

# 3. Sync to the Dolt system of record + push to DoltHub (tags run-N)
python3 freshie/scripts/dolt-sync.py

# Then commit the refreshed grades.csv / grade-histogram.json with your PR.
```

Other operations:

```bash
python3 freshie/scripts/rebuild-inventory.py --export    # CSV export per run
python3 freshie/scripts/rebuild-inventory.py --diff      # compare runs
python3 freshie/scripts/rebuild-inventory.py --dry-run   # scan preview
python3 freshie/scripts/dolt-sync.py --dry-run           # show translated DDL
python3 freshie/scripts/dolt-sync.py --no-push           # local sync only
python3 -m unittest tests.test_dolt_sync -v              # exporter unit tests
```

## Querying

**Runtime (local SQLite)** — unchanged:

```bash
sqlite3 freshie/inventory.sqlite "SELECT grade, COUNT(*) FROM skill_compliance GROUP BY grade;"
```

**History (Dolt)** — the run_id model is append-only, so `dolt diff` between
run tags shows *added rows*, not cell changes. History questions are asked
with `WHERE run_id = N` or `AS OF`:

```bash
cd freshie/dolt/freshie

dolt sql -q "SELECT grade, COUNT(*) FROM skill_compliance WHERE run_id = 8 GROUP BY grade;"
dolt sql -q "SELECT * FROM skill_compliance AS OF 'run-7' WHERE skill_path LIKE '%tonone%';"
dolt diff run-7 run-8 --stat
dolt log --oneline
```

**Clone-free (DoltHub API)** — check the public record without cloning:

```bash
curl -s "https://www.dolthub.com/api/v1alpha1/jeremylongshore/freshie-inventory/main?q=SELECT+COUNT(*)+FROM+skill_compliance"
```

## Restore path (DoltHub → fresh local SQLite)

If the local `inventory.sqlite` is ever lost:

```bash
dolt clone jeremylongshore/freshie-inventory && cd freshie-inventory
for t in $(dolt sql -r csv -q "SHOW TABLES" | tail -n +2); do
  dolt sql -r csv -q "SELECT * FROM \`$t\`" > "$t.csv"
  sqlite3 new-inventory.sqlite ".import --csv $t.csv $t"
done
```

(Types come back as text affinity — good enough for reads; the next
`rebuild-inventory.py` run regenerates a fully-typed DB anyway.)

## How the exporter works (dolt-sync.py)

- **Schema translation:** INTEGER→BIGINT, REAL→DOUBLE, TIMESTAMP→DATETIME(6),
  TEXT→LONGTEXT (TEXT primary keys → VARCHAR(255) with a length guard);
  AUTOINCREMENT stripped; every identifier backticked; BLOB is a hard fail.
  Columns whose *data* violates their declared type (SQLite typing is
  advisory) are widened to LONGTEXT with a loud log line.
- **Pump:** `sqlite3 -header -csv` → `dolt table import -r`. NULL vs `''`
  round-trips without a sentinel (a fixture canary re-proves it every run;
  on canary failure, empty-string-bearing tables fall back to batched
  INSERTs).
- **Gates before commit:** per-table `COUNT(*)` parity, float-tolerant
  checksums on REAL columns, per-row MD5 byte checksums on the JSON-bearing
  TEXT columns.
- **Commit/tag/push:** `dolt commit --skip-empty`; tag `run-N` only when it
  tells the truth; the tag is pushed explicitly (tags don't ride along on a
  branch push). Push failure = non-zero exit, loud.
- **Hygiene:** `dolt gc` runs under the sync lock every 5 syncs or when the
  repo dir doubles. Concurrency-guarded by an flock + a running-sql-server
  refusal.

CI runners need a Dolt commit identity
(`dolt config --global --add user.name/user.email`) and can push with
`dolt push --user <name>` + `DOLT_REMOTE_PASSWORD=<api token>` instead of
`dolt login` creds.

## Database Design

**51 tables** organized in groups:

| Group | Tables | What |
|-------|--------|------|
| Core entities | packs, plugins, skills | The ecosystem topology |
| Metadata | frontmatter_*, plugin_* | YAML/JSON field analysis |
| File analysis | skill_files, content_signals, duplicates | Deep file scanning |
| Components | command_files, agent_files | Slash commands & agents |
| Compliance | skill/agent/plugin_compliance | Validator scores & grades |
| Infrastructure | scripts, validators, ci_workflows | Build system catalog |
| Dependencies | npm_* | npm registry intelligence |
| Documentation | docs | All .md files cataloged |

**Versioned runs:** Every table has a `run_id` column. Query by run to see point-in-time snapshots. Compare runs to track changes. Each sync additionally tags the Dolt history `run-N`.
