## Purpose

Security testing is not a single tool — it is seven distinct test layers
that together answer: *could an attacker compromise this repo's output*?
The sweep verifies every layer relevant to the repo shape (app,
container, IaC, mixed) is running in CI with failing exit codes.

This reference complements the `specialized-testing.md` §Security section
(which focuses on unit-test level security assertions) with the
*systemic* security gates that belong at the CI boundary.

## Threat-Model-First

Before prescribing tools, the sweep asks:

1. **What runs this code?** (browser / server / device / k8s pod / lambda)
2. **What data does it touch?** (user PII / financial / auth tokens / public)
3. **What's the supply chain?** (npm / pypi / crates / OCI images / terraform modules)
4. **What's the deployment surface?** (public URL / private VPN / side-loaded app)

Answers determine which layers are P0 vs P1. E.g., a static site has no
DAST target but has strong IaC exposure; a CLI has no DAST but heavy SAST

- dep-audit focus.

## SAST (Static Application Security Testing)

Code-level analysis for security bugs — SQL injection, XSS, command
injection, path traversal, insecure deserialization, weak crypto.

### Language-agnostic

| Tool | Model | Notes |
|---|---|---|
| **Semgrep** | Pattern-based rules (OPA-style) | Community rules + custom. Fast, permissive license. |
| **SonarQube** / **SonarCloud** | Engine + community rules | Self-hosted (Community edition) or SaaS. |
| **CodeQL** | Semantic code graph | GitHub-native. Free for public repos. Heavy for big codebases but deep. |
| **Snyk Code** | Commercial, DeepCode-based | SaaS, per-seat pricing. |

Semgrep quick-start:

```bash
# Local scan
semgrep --config auto .
# Focused on OWASP Top 10
semgrep --config p/owasp-top-ten .
# CI
semgrep ci --config p/r2c-security-audit
```

GitHub Actions (CodeQL):

```yaml
# .github/workflows/codeql.yml — generated by `gh codeql init`
jobs:
  analyze:
    runs-on: ubuntu-latest
    permissions: { security-events: write }
    steps:
      - uses: actions/checkout@v4
      - uses: github/codeql-action/init@v3
        with: { languages: javascript, python }
      - uses: github/codeql-action/autobuild@v3
      - uses: github/codeql-action/analyze@v3
```

### Language-specific

| Language | Tool |
|---|---|
| Python | **Bandit** (python-specific SAST), Dlint (django), Semgrep |
| Ruby | **Brakeman** (Rails-specific, gold standard), RuboCop with rubocop-rails |
| JavaScript/TS | **NodeJsScan**, ESLint with `eslint-plugin-security` |
| Java | **SpotBugs + FindSecBugs** plugin |
| .NET | Security Code Scan, Roslyn Security Analyzer |
| Go | **gosec** (`go install github.com/securego/gosec/v2/cmd/gosec@latest`) |
| Rust | `cargo-geiger` (unsafe surface), `cargo-audit` |
| PHP | **Psalm** with taint analysis (`--taint-analysis`), RIPS |
| Scala | Scapegoat |

### AI-generated code concerns

Modern SAST should include `eslint-plugin-security` + Semgrep's
`p/ai-generated` ruleset. Bulk LLM-written code has characteristic
patterns of weak validation and happy-path-only assertions.

## DAST (Dynamic Application Security Testing)

Runtime testing against a deployed app — discovers injection flaws, auth
bypasses, misconfigurations that SAST can't see.

| Tool | Model |
|---|---|
| **OWASP ZAP** | Open-source, proxy + active scanner. Can run headless in CI. |
| **Burp Suite** | Commercial, industry standard, heavier. |
| **Nuclei** (ProjectDiscovery) | Template-driven fast scanner, great for known CVEs. |
| **w3af** | OSS, Python, less maintained but still useful. |
| **Arachni** | Ruby-based, legacy. |

ZAP in CI (against ephemeral staging):

```yaml
- uses: zaproxy/action-baseline@v0.13.0
  with:
    target: 'https://staging.example.com'
    rules_file_name: '.zap/rules.tsv'
    fail_action: true
```

Nuclei:

```bash
nuclei -u https://example.com -severity critical,high
```

DAST requires a live target — typically run post-deploy against staging,
not in the PR pipeline.

## Secrets Scanning

Stops committed credentials before they reach remote.

| Tool | Scope |
|---|---|
| **gitleaks** | Fast, Go-based, large rule library, git-history scan. Industry default. |
| **trufflehog** | Python/Go, emphasizes entropy + verification (validates tokens live). |
| **detect-secrets** (Yelp) | Python, excels at baselining existing findings. |
| **git-secrets** (AWS) | AWS-credential-focused. |
| **ggshield** (GitGuardian) | SaaS + OSS CLI; commercial validation. |

gitleaks pre-commit + CI:

```yaml
# .pre-commit-config.yaml
- repo: https://github.com/gitleaks/gitleaks
  rev: v8.18.0
  hooks: [{ id: gitleaks }]

# .github/workflows/gitleaks.yml
- uses: gitleaks/gitleaks-action@v2
  env: { GITLEAKS_LICENSE: ${{ secrets.GITLEAKS_LICENSE }} }
```

Full history scan: `gitleaks detect --source . --verbose --redact`.

**Remediation if a secret is found:** rotate the credential first; THEN
scrub git history (`git-filter-repo`, BFG). Do not skip rotation.

## Dependency Vulnerability Scanning

Find known-vulnerable dependencies before they ship.

### Per-language

| Ecosystem | Tool(s) |
|---|---|
| npm / yarn / pnpm | `npm audit`, `pnpm audit`, **Snyk**, **Socket** |
| PyPI | **pip-audit** (PyPA), Safety, Snyk |
| Cargo | `cargo audit`, `cargo deny` |
| Go modules | **govulncheck** (official) + nancy (Sonatype) |
| Maven / Gradle | **OWASP Dependency-Check**, Snyk |
| RubyGems | `bundle audit` / bundler-audit |
| Composer (PHP) | Roave Security Advisories, `composer audit` |
| NuGet (.NET) | `dotnet list package --vulnerable` |
| Hex (Elixir) | `mix hex.audit`, mix_audit |
| CRAN (R) | oysteR |

### Cross-ecosystem

| Tool | Notes |
|---|---|
| **Trivy** (Aqua) | Scans all above + containers + IaC in one binary. |
| **OSV-scanner** (Google) | Uses OSV.dev DB; ecosystem-agnostic. |
| **Snyk** | SaaS with broad coverage. |
| **GitHub Advanced Security** | Native to GitHub; Dependabot + secret scanning + code scanning. |
| **Dependabot** | Automated PR bumps; configure via `.github/dependabot.yml`. |
| **Renovate** | Same idea, more configurable. Self-hosted option. |

Trivy one-liner:

```bash
trivy fs . --severity CRITICAL,HIGH --exit-code 1
trivy image <image-ref> --severity CRITICAL,HIGH --exit-code 1
```

### Automated dependency updates

**Every repo should have one of:**

- `.github/dependabot.yml` (GitHub-native)
- `renovate.json` (self-hosted or Renovate Bot)
- Scheduled `cargo update` / `npm update` / `pip-upgrade` cron (fallback)

## Container Image Scanning

If the repo builds or references OCI images:

| Tool | Notes |
|---|---|
| **Trivy** | Layer-by-layer CVE scan + misconfiguration + secrets. Industry default. |
| **Grype** (Anchore) | Fast, OSV-based. |
| **Docker Scout** | Integrated into Docker Desktop + Hub. |
| **Snyk Container** | SaaS. |
| **Anchore Engine** | Self-hosted, policy-driven. |

In CI:

```yaml
- uses: aquasecurity/trivy-action@master
  with:
    image-ref: ${{ env.IMAGE }}
    exit-code: 1
    severity: CRITICAL,HIGH
    ignore-unfixed: true
```

Dockerfile-level static check: **hadolint**.

```bash
hadolint Dockerfile
```

Minimize attack surface: distroless images (`gcr.io/distroless/*`), or
scratch + static binaries (Go, Rust).

## OWASP Top 10 — per-category test checklist

The OWASP Top 10 (2021) maps to concrete tests the sweep expects:

| Category | Test layer | Expected |
|---|---|---|
| **A01 Broken Access Control** | Unit + integration + DAST | Tests for auth bypass, forced browsing, IDOR; ZAP active scan |
| **A02 Cryptographic Failures** | SAST + unit | Semgrep/CodeQL for weak algs (MD5, SHA-1, DES); unit tests asserting TLS-only cookies |
| **A03 Injection** | SAST + unit + DAST | SQLi / XSS / cmd-i rules; parametrized query assertions; ZAP injection scans |
| **A04 Insecure Design** | Threat-model review | Documented threat model (STRIDE / LINDDUN); design doc in `/docs/security/` |
| **A05 Security Misconfig** | IaC scan + DAST + unit | Checkov/Trivy on IaC; ZAP header checks; unit tests on CORS/CSP middleware |
| **A06 Vulnerable & Outdated Components** | Dep audit | pip-audit / npm audit / Trivy / govulncheck — **P0 in CI** |
| **A07 Authentication Failures** | Unit + integration | Rate-limit tests, brute-force, session fixation, password policy |
| **A08 Software & Data Integrity Failures** | Supply-chain | SBOM, signed artifacts, Sigstore, SLSA level 2+, locked lockfiles |
| **A09 Logging & Monitoring Failures** | Observability tests | Assert audit log is produced for security-relevant actions |
| **A10 SSRF** | SAST + unit + DAST | URL validation tests; Semgrep SSRF rules; ZAP active scan |

The sweep reports the OWASP category → test coverage mapping as a
sub-table of the `QUALITY_GATES.md`.

## Supply-Chain & Provenance

Post-SolarWinds / log4shell / xz, the bar for production releases includes:

- **SBOM** (Software Bill of Materials) — `Syft` (Anchore), CycloneDX tools, SPDX.
- **SLSA level 2+** — build provenance attestation via slsa-github-generator.
- **Signed artifacts** — Cosign (containers + arbitrary blobs), Minisign, GPG.
- **Sigstore keyless signing** — OIDC-backed, no long-lived keys.
- **Reproducible builds** — deterministic outputs for independent verification (`diffoscope`).
- **Locked dependencies** — `package-lock.json` / `Cargo.lock` / `uv.lock` / `go.sum` / `Gemfile.lock` committed.

CI snippet — generate + attach SBOM:

```yaml
- uses: anchore/sbom-action@v0
  with:
    path: .
    format: cyclonedx-json
    artifact-name: sbom.cdx.json
- uses: actions/upload-artifact@v4
  with: { name: sbom, path: sbom.cdx.json }
```

## License & Compliance

Preventing GPL contamination in proprietary projects, AGPL surprises,
etc.

| Tool | Notes |
|---|---|
| **FOSSA** | SaaS, thorough. |
| **licensed** (GitHub) | CLI, config-driven. |
| **license-finder** (Pivotal) | CLI, many ecosystems. |
| **askalono** | Rust-based, fast ID. |
| **scancode-toolkit** | OSS, very thorough, slower. |

License posture is P2 for OSS, P0 for proprietary commercial products.

## Enforcement Checklist

- [ ] SAST running in CI on PR (Semgrep / CodeQL / Bandit / gosec / Brakeman, language-appropriate)
- [ ] Secrets scan running in CI on PR (gitleaks / trufflehog)
- [ ] Secrets scan running pre-commit (gitleaks / detect-secrets)
- [ ] Dep vuln scan running in CI (pip-audit / npm audit / cargo audit / govulncheck / Trivy)
- [ ] Automated dep-update bot enabled (Dependabot / Renovate)
- [ ] Container image scan running post-build (if Docker)
- [ ] IaC scan running in CI (if Terraform / k8s / CFN)
- [ ] OWASP Top 10 categories covered by tests (see table above)
- [ ] DAST against staging post-deploy (for public-facing apps)
- [ ] SBOM generated per release
- [ ] Artifacts signed (container + tarball + whatever ships)
- [ ] License check in CI (for commercial code)
- [ ] No hardcoded secrets in history (full-repo gitleaks sweep passes)
