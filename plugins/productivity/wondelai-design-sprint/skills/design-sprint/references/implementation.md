# Design Sprint -- 5-Day Process Implementation Guide

## Overview

Run Google Ventures' Design Sprint (Understand, Diverge, Decide, Prototype, Test) to validate product ideas and solve complex problems in 5 days.

## Day-by-Day Process

### Day 1: Understand (Monday)

Goal: Align the team on the problem and long-term goal.

```markdown
## Day 1 Agenda

Morning:
- Lightning talks (15 min each): Each expert shares their perspective
- How Might We (HMW) notes: Everyone writes HMW questions on stickies
- HMW clustering: Group similar questions

Afternoon:
- Sprint questions: "What could cause this to fail?"
- Target: Choose ONE user and ONE moment to focus on this week
- Map: Draw a simple customer journey map (actors + steps)

Deliverable:
- Sprint goal statement: "By Friday, we will know if [assumption] is true."
- Target moment: "[User] is at the moment when [step on map]."
```

### Day 2: Diverge (Tuesday)

Goal: Generate many possible solutions independently.

```markdown
## Day 2 Agenda

Morning:
- Lightning demos (3 min each): Show inspiring solutions from other products
- Individual note-taking: 20 minutes, review notes from Day 1

Afternoon:
- Crazy 8s: Fold paper in 8 panels, sketch 8 ideas in 8 minutes
- Solution sketch: 3-panel storyboard, anonymous, with a catchy title
- No group brainstorming -- individual work prevents anchoring bias
```

### Day 3: Decide (Wednesday)

Goal: Choose the best idea to prototype.

```markdown
## Day 3 Agenda

Morning:
- Art museum: Post all solution sketches silently
- Heat map voting: Everyone places dot stickers on compelling elements
- Speed critique: 3 min per sketch, note standout ideas

Afternoon:
- Straw poll vote: Each person votes on their top concept
- Decider vote: Decision maker makes final call (with input from team)
- Storyboard: Map out 8-15 panels of what will be prototyped
```

### Day 4: Prototype (Thursday)

Goal: Build a realistic-enough prototype to test with users.

```markdown
## Day 4 Roles

Maker 1 & 2: Build components in Figma / on paper
Stitcher: Assemble components into a coherent flow
Writer: Write all copy / microcopy
Asset collector: Gather images, icons, real data for realism
Interviewer: Write the interview script for Friday

Tools: Figma, Keynote, Marvel, InVision, or paper
Rule: The prototype only needs to LOOK real, not work
Target: High fidelity enough to evoke real reactions
```

### Day 5: Test (Friday)

Goal: Interview 5 users with the prototype.

```markdown
## Interview Structure (60 min each)

0-5 min:  Friendly introduction, set expectations, get consent to record
5-15 min: Background questions (understand their context)
15-50 min: Prototype walkthrough (give tasks, observe, don't lead)
50-60 min: Debrief, final questions

Interview script template:
"Pretend this is a real product you've just encountered.
Think out loud as you use it.
I'm testing the product, not you -- there are no wrong answers."
```

## Sprint Logistics Checklist

```markdown
Pre-sprint:
- [ ] 5-7 person team confirmed (decider, facilitators, builders)
- [ ] 5 test participants recruited matching target persona
- [ ] Dedicated room booked for 5 days (whiteboard walls ideal)
- [ ] Materials: stickies, markers, dot stickers, timer, large paper

Supplies:
- [ ] Crazy 8s paper (A4 folded in thirds twice)
- [ ] Solution sketch paper (3-panel template)
- [ ] Dot stickers (voting)
- [ ] Sharpies (forces concise writing)
```
