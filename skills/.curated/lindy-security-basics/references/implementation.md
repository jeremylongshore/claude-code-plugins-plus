# Lindy Security Basics -- Receiver-Owned Boundary

## Purpose

This example protects an application endpoint called by a Lindy HTTP Request action.
The bearer value belongs to the application receiver; it is not a Lindy API key,
Webhook Received secret, or claimed Lindy callback signature.

```python
import hmac
import os
import re
from flask import Flask, jsonify, request

app = Flask(__name__)
app.config["MAX_CONTENT_LENGTH"] = 4096

callback_secret = os.environ.get("APP_LINDY_CALLBACK_SECRET", "")
if len(callback_secret) < 32:
    raise RuntimeError("APP_LINDY_CALLBACK_SECRET must contain at least 32 characters")

REFERENCE = re.compile(r"^job_[A-Za-z0-9_-]{1,64}$")
STATUSES = {"completed", "failed", "needs_review"}


def authorized(header: str) -> bool:
    prefix = "Bearer "
    if not header.startswith(prefix):
        return False
    return hmac.compare_digest(header[len(prefix):], callback_secret)


def parse_result(value: object) -> dict:
    if not isinstance(value, dict) or set(value) != {"reference", "status"}:
        raise ValueError("unexpected result schema")
    reference = value.get("reference")
    status = value.get("status")
    if not isinstance(reference, str) or not REFERENCE.fullmatch(reference):
        raise ValueError("invalid reference")
    if status not in STATUSES:
        raise ValueError("invalid status")
    return {"reference": reference, "status": status}


@app.post("/workflow-result")
def workflow_result():
    if not authorized(request.headers.get("Authorization", "")):
        return jsonify({"error": "unauthorized"}), 401
    try:
        result = parse_result(request.get_json(force=False, silent=False))
    except (TypeError, ValueError):
        return jsonify({"error": "invalid_schema"}), 400

    # Persist a staged status only. Do not log the body or perform a side effect.
    stage_for_review(result["reference"], result["status"])
    return jsonify({"accepted": True}), 202
```

## Deployment Rules

- Generate `APP_LINDY_CALLBACK_SECRET` in the receiver's secret manager and place the
  same protected value only in the corresponding Lindy HTTP Request header.
- Keep it distinct from the secret generated by an inbound Webhook Received trigger.
- Terminate TLS at an approved endpoint and restrict the route at the platform layer
  where available.
- Add replay/idempotency protection appropriate to the application's operation model;
  do not claim Lindy provides a header or signing scheme that its docs do not state.
- Stage results for schema/business validation and approval before consequential use.
- Log only bounded operational metadata; never log Authorization or the request body.

## Verification

Test a valid bounded result, wrong/missing secret, extra/missing field, unknown status,
invalid/oversized reference, oversized body, repeated operation, and downstream
review rejection. Each invalid case must cause no business side effect.

## Exposure Response

If a generated webhook secret, receiver credential, webhook URL, or connected-account
credential is exposed, stop the affected path, preserve sanitized evidence, rotate or
reconfigure the credential using the owning system's current UI, verify the new
boundary, retire the old value, and review Tasks/receiver metadata for misuse. Do not
publish the value while removing it from source history or tickets.
