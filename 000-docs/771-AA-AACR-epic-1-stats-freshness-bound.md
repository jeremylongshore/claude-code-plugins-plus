## Outcome

The three external stats artifacts — `github-stats.json` (stars), `npm-stats.json` (downloads),
`skills-stats.json` (skills.sh installs) — now each declare `max_age_hours: 72` beside
`generatedAt`, and the bound is enforced at three independent layers. These are the only
marketplace numbers not regenerated from the corpus at build time: their fetchers fail soft by
design and their daily refresh lands via an automation PR that needs a human merge. At activation,
main's tracked copies were 381–498 hours (16–20 days) stale while the homepage rendered them as
current — the exact rot class blueprint row 26 names.

Scorecard row `external_stats_bound` moved from `without_valid_bound: 3` to `0`.

## Root cause of the observed staleness

The daily `update-npm-stats.yml` workflow pushes its branch with `GITHUB_TOKEN`, which cannot
trigger required workflows (GitHub anti-recursion). Every daily PR therefore sat with **zero check
runs** and could never merge; the refresh ran faithfully every day into a branch nobody could
land. An owner-authored empty commit retriggered the suite on PR #1149, which merged during this
slice and reset the clock. The durable repair — a `BOT_PR_TOKEN` fine-grained PAT the workflow
already supports — remains an owner console action and is recorded as follow-up.

## Implemented controls

1. **Declared bound in the artifact** — each fetch script stamps `max_age_hours: 72` (3× the
   daily cadence) into its output, and the tracked copies carry it now. The bound lives in the
   artifact, not the checker, so a future snapshot with a different cadence declares its own
   tolerance.
2. **`scripts/check-stats-freshness.mjs`** — deterministic checker with two violation classes:
   `structural` (unreadable artifact, missing/invalid `generatedAt` or `max_age_hours`) and
   `stale` (age past bound). Default mode fails on both; `--report` mode fails only on
   structural.
3. **Daily workflow gates** — `update-npm-stats.yml` reports tracked staleness before fetching
   (surfaces automation-PR merge lag without failing the run that fixes it) and hard-fails after
   fetching if even freshly written output breaches the bound (persistent upstream API rot that
   fail-soft fetches would hide forever).
4. **PR CI structural gate** — `doc-governance` runs `validate:stats-freshness` (tests + report
   mode), so removing a declaration fails every PR deterministically, while a time-based breach
   can never spontaneously block unrelated merges. That loud failure belongs to the daily
   workflow, not to PR CI.
5. **Render-side refusal** — `marketplace/src/pages/index.astro` treats an out-of-bound artifact
   exactly like a missing one: the stars/installs lines are omitted rather than rendered stale.
   The page can no longer present an out-of-bound external number as current even if every other
   gate is bypassed.

## Verification

- `node --test scripts/check-stats-freshness.test.mjs` — 6/6 pass, covering both violation
  classes, invalid-bound rejection (`0`, negative, non-numeric, `NaN`, `Infinity`), directory
  sweep, the governed-set pin, and a declaration assertion against the tracked artifacts.
- Default mode exited 1 naming all three 381–498h breaches against the pre-slice artifacts, and
  exits 0 (`3/3 fresh`) against the post-#1149 artifacts with bounds stamped.
- `--report` mode exited 0 on stale-but-declared artifacts and fails on a missing declaration.
- `pnpm run validate:generated-artifacts` OK; scorecard and docs index regenerated by their
  canonical writers and re-verified in check mode; prettier/eslint clean.

## Scope discipline

No plugin, skill, `.source.json`, provenance-owned mirror, package version, registry artifact,

`automation/npm-stats` PR #1149 was repaired (merge of current main + README TOC regeneration)
and merged as a prerequisite so the bound could be stamped onto fresh data rather than onto
16–20-day-old numbers.
