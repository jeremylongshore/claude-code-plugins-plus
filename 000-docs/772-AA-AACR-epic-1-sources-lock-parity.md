## Owner reshaping of the blueprint disposition

Blueprint row 27 prescribed **removing** the orphan `uizze` external source. The owner decided
otherwise on 2026-08-18: the UIZZE mirror was accepted and restored via PR #1242 (author
`samuelbushi`), which this program repaired (merge of current main + Epic 1 scorecard
regeneration) and merged. With the source legitimate, E1.12's residual defect was narrower but
real: `uizze` sat registered in `sources.yaml` with **no `sources.lock.json` baseline**, so its
next weekly sync would have mirrored upstream unpinned — outside the content-pinning threat model
`scripts/sync-lockfile.mjs` documents — and nothing prevented the registered-but-unlocked class
from recurring. PR #1242 had also restored the plugin directory without its
`marketplace.extended.json` catalog entry.

## Outcome

- `uizze` now has a reviewed lock baseline, advanced via the sanctioned
  `node scripts/sync-external.mjs --source=uizze --relock=uizze` path. The relock also completed
  the missing catalog entry (467 → 468 plugins) and refreshed the mirror to current upstream copy
  (description rewording and directory-listing links — reviewed, benign).
- New gate `scripts/check-sources-lock-parity.mjs` asserts the `sources.yaml` name set equals the
  `sources.lock.json` key set **in both directions**: a registered-but-unlocked source and an
  orphaned lock entry are both loud failures naming the offender and the sanctioned fix. Wired as
  `validate:sources-lock-parity` in the `validate` job, blocking through `ci-required`.
- Parity at filing: **64 registered == 64 locked**.

Chose a standalone whole-repo parity checker over extending the diff-scoped intake ratchet: the
ratchet is grandfathered and `pull_request`-only by design, while parity is an every-event
invariant.
